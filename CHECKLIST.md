## 1. СИЛЬНІ СТОРОНИ

- [x] **Чиста модульна архітектура** — 11 модулів з чітким розділенням відповідальностей (SRP). Кожен модуль має одну зону відповідальності.
- [x] **Observer Pattern для стейту** — `StateManager` з pub/sub дає реактивне оновлення UI без фреймворків.
- [x] **ABC-аналіз (Парето)** — коректна реалізація 80/15/5 класифікації з автоматичним розрахунком.
- [x] **Мультиформатний імпорт** — підтримка CSV (PapaParse) та Excel (XLSX) з евристичним виявленням заголовків.
- [x] **Конвертація валют** — живі курси з open.er-api.com + fallback-курси для офлайн-роботи.
- [x] **Двомовність (UA/EN)** — 64 ключі перекладу для обох мов у `constants.js`.
- [x] **6 інтерактивних графіків** — Chart.js з data labels, клікабельними елементами та тултіпами.
- [x] **Single-file deployment** — збірка в один HTML через `vite-plugin-singlefile`, зручно для дистрибуції.
- [x] **Responsive дизайн** — mobile-first підхід з Tailwind CSS, адаптація під sm/md/lg/xl.
- [x] **Розумний пошук** — по імені клієнта та номеру телефону одночасно.
- [x] **Виявлення прихованого бізнесу** — автодетекція "Private person" з 3+ відправками.
- [x] **Пагінація** — 50 рядків на сторінку для великих датасетів.
- [x] **GitHub Pages CI/CD** — автодеплой через GitHub Actions при пуші в main.

## 2. КРИТИЧНІ ПРОБЛЕМИ (Пріоритет: ВИСОКИЙ)

### 2.1 Безпека

- [ ] **XSS-вразливість через `innerHTML`** — Дані з файлів вставляються в DOM через `innerHTML` без санітизації. Імена клієнтів, товарів, країн — все може містити шкідливий скрипт.
  - Файли: `TableRenderer.js:46`, `DashboardRenderer.js:24-29`, `ModalManager.js:34`, `FilterManager.js:81-84`
  - Рішення: використовувати `textContent` або DOMPurify для всіх динамічних даних.

- [ ] **Відсутність валідації файлів** — Немає перевірки розміру файлу, MIME-типу, або кількості рядків перед обробкою. Величезний файл може заморозити браузер.
  - Файл: `DataEngine.js:11-41`
  - Рішення: додати ліміт на розмір файлу (напр. 50MB), перевірку типу, та попередження при >100k рядків.

### 2.2 Баги в коді

- [ ] **Перемикач мов не працює** — `langToggle` (index.html:82) слухається, але ніде в коді немає логіки перемикання `data-i18n` атрибутів. Переклад існує в `TRANSLATIONS`, але не застосовується.
  - Файли: `index.html:82`, `constants.js:31-164`
  - Рішення: додати в `App.js` або `UIManager.js` функцію `applyTranslations(lang)` що оновлює всі `[data-i18n]` елементи.

- [ ] **Закриття модалу не працює** — `App.js:59` шукає `#closeModal`, але в HTML є `#btnCloseModal`. Кнопка "X" в модалі не працює.
  - Файли: `App.js:59`, `index.html:401`
  - Рішення: змінити `closeModal` на `btnCloseModal` в `App.js:59`.

- [ ] **Модальне вікно не анімується** — `modalPanel` має класи `scale-95 opacity-0` які ніколи не прибираються (index.html:393). Модал відкривається невидимим.
  - Рішення: прибрати `opacity-0 scale-95` або додати JS-логіку анімації при відкритті/закритті.

- [ ] **KPI "Всього Клієнтів" показує кількість відправок** — `DashboardRenderer.js:12` записує `res.totalShipments` в елемент з id `totalClients`. Плутанина між клієнтами та відправками.
  - Рішення: додати `res.clients.length` як окреме значення, або виправити label.

- [ ] **Рік в footer захардкоджений** — `index.html:383` показує "2024", `#currentYear` ніде не оновлюється динамічно.
  - Рішення: додати `document.getElementById('currentYear').textContent = new Date().getFullYear()` в `main.js`.

- [ ] **Бейдж курсу та періоду ніколи не показується** — `#rateBadge` та `#periodBadge` мають клас `hidden`, який ніде не знімається після завантаження курсів та виявлення дат.
  - Файли: `index.html:64-73`, ніде в JS не знімається `hidden`
  - Рішення: додати логіку показу бейджів після `fetchRates()` та аналізу дат.

- [ ] **Сортування таблиці не реалізовано** — Заголовки мають `data-sort` атрибути та "стрілки" ↕, але жодного обробника подій для сортування немає.
  - Файл: `index.html:322-338`, `TableRenderer.js` — відсутній код сортування
  - Рішення: додати `sortBy` в StateManager та обробник кліку на `<th>`.

- [ ] **Дебаг-коментарі залишені в продакшн-коді** — `App.js:109-161` містить 50 рядків внутрішніх роздумів розробника (не коментарі коду, а "ноти до себе").
  - Рішення: видалити або переписати як нормальні коментарі.

### 2.3 Архітектурні проблеми

- [ ] **Логіка модалу розмазана між 3 файлами** — відкриття в `ModalManager.js`, закриття в `App.js:57-68`, обробка кліку в `TableRenderer.js:65-67`.
  - Рішення: перенести ВСЮ логіку модалу (відкриття, закриття, події) в `ModalManager.js`.

- [ ] **`getFilteredClients()` викликається багаторазово без кешування** — Кожен виклик заново фільтрує весь масив. При 10k+ клієнтів це помітно.
  - Файл: `StateManager.js:59-86`
  - Рішення: кешувати результат, інвалідувати при `setFilter()`.

- [ ] **Подвійна фільтрація** — `AnalyticsEngine.analyze()` фільтрує по origins/dests/segment (рядок 33-48), а потім `StateManager.getFilteredClients()` фільтрує ЗНОВУ по тих самих полях (рядок 59-86). Дублювання логіки.
  - Рішення: чітко розділити — AnalyticsEngine для агрегації, StateManager тільки для UI-фільтрів (search, abc).

## 4. ПРОБЛЕМИ НИЗЬКОГО ПРІОРИТЕТУ

### 4.1 Продуктивність

- [ ] **Немає Web Workers** — Обробка великих файлів (100k+ рядків) блокує main thread. UI замерзає.
  - Рішення: перенести `DataEngine.processCSV/Excel` та `AnalyticsEngine.analyze` у Web Worker.

- [ ] **Chart.js рендерить 6 графіків синхронно** — Кожен `_createBarChart` блокує main thread.
  - Рішення: requestAnimationFrame або послідовний рендеринг з мікрозатримками.

- [ ] **Tailwind CSS з CDN** — Завантажує повний runtime (~300KB), хоча використовується лише частина утиліт. Не працює офлайн.
  - Рішення: перейти на Tailwind CLI або PostCSS плагін — bundle тільки використані класи.

- [ ] **Немає lazy rendering для таблиці** — DOM створюється для 50 рядків одразу через innerHTML. При швидкому перемиканні сторінок може бути помітно.
  - Рішення: віртуальний скролінг або DocumentFragment.

### 4.2 Доступність (Accessibility)

- [ ] **Немає ARIA-атрибутів** — Графіки, модал, пагінація, фільтри не мають aria-labels.
  - Рішення: додати `role`, `aria-label`, `aria-live` для динамічних секцій.

- [ ] **Немає клавіатурної навігації** — Таблиця не підтримує Tab/Enter, модал не закривається на Escape.
  - Рішення: додати keyboard event handlers (Escape для модалу, Enter для рядків таблиці).

- [ ] **Низький контраст тексту** — `text-gray-400`, `text-gray-500` на білому фоні не проходять WCAG AA.
  - Рішення: підвищити контраст до мінімум `text-gray-600`.

- [ ] **Немає focus-visible стилів** — Інтерактивні елементи не мають видимого focus outline.
  - Рішення: додати `focus-visible:ring-2` для всіх кнопок та інпутів.

### 4.3 Інфраструктура

- [ ] **Немає error reporting** — Помилки потрапляють тільки в console.error. Користувач бачить generic alert.
  - Рішення: додати toast-повідомлення з деталями помилки, або error boundary UI.

- [ ] **Немає analytics/telemetry** — Невідомо які функції використовуються, які файли завантажуються.
  - Рішення: опціональний lightweight analytics (напр. Plausible) або console-based usage logging.

- [ ] **Немає versioning у UI** — Версія захардкоджена в title. При оновленнях незрозуміло яка версія.
  - Рішення: читати version з package.json або env variable під час збірки.

- [ ] **GitHub Actions деплой не має preview** — PR-и не мають preview deploy для тестування.
  - Рішення: додати preview environment в workflow для PR-ів.
